# pdpa

ทำเว็บ/ธุรกิจให้ตรง **PDPA ไทย** + ครอบการใช้ **AI**. ออกเอกสาร + โค้ด consent + ช่องทางสิทธิ ติดตั้งลงเว็บได้. ทำกับเว็บที่มี หรือเว็บที่ build จาก company-website/sale-page.

## แพลตฟอร์ม + ใครกด deploy (อ่านก่อน)

**self-contained ไม่พึ่ง skill นอก. ทำงานได้ 2 ช่องทาง:**
- **Claude Code (desktop)** — trigger / `/pdpa`
- **ChatGPT Codex** — ชี้มาที่ไฟล์นี้ หรือก็อปลง `AGENTS.md`/prompt. ไม่พึ่ง path `~/.claude/...`

**ติดตั้งลงเว็บ live:** เตรียมเป็น preview → **เจ้าของ/ผู้ดูแลอนุมัติ → ค่อยขึ้น prod**.

## ⚠️ ข้อจำกัด (พูดกับ user ตั้งแต่ต้น)
skill นี้ทำ compliance พื้นฐานให้เว็บทั่วไป **ไม่ใช่คำปรึกษากฎหมาย**. ธุรกิจข้อมูลอ่อนไหว (สุขภาพ/การเงิน/เด็ก) หรือเก็บข้อมูลเยอะ → ให้ทนาย/DPO ตรวจก่อนใช้จริง.

## ⭐ ผู้ใช้ = เจ้าของธุรกิจ ไม่เก่งเทค
- **ภาษาชาวบ้าน** — ไม่พูด "lawful basis/data controller" ลอยๆ. อธิบายว่าทำไมต้องทำ + ป้องกันอะไร (โดนปรับ/ฟ้อง)
- **ถามทีละคำ + เสนอคำตอบแนะนำ** (grill-me) · ขาดข้อมูลถามเลย
- **สรุปให้ยืนยันก่อนออกเอกสาร**

## PDPA ย่อ (เบื้องหลัง)
พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล 2562 (บังคับใช้เต็ม 1 มิ.ย. 2565). เว็บที่เก็บข้อมูลคน (ชื่อ/เบอร์/อีเมล/คุกกี้/IP) = ต้องมี **ฐานการประมวลผลที่ชอบด้วยกฎหมาย + แจ้งวัตถุประสงค์ + ให้สิทธิเจ้าของข้อมูล**. โทษ: ปกครอง/แพ่ง/อาญา (ปรับสูงสุดหลักล้าน).

---

## Phase 0 — สัมภาษณ์ (map ว่าเก็บอะไร)

ถามทีละคำ (เสนอคำตอบแนะนำ):
1. "เว็บ/ธุรกิจเก็บข้อมูลอะไรจากลูกค้าบ้าง?" *(ฟอร์มชื่อ-เบอร์-อีเมล / แชท / สมัครสมาชิก / ชำระเงิน)*
2. "เก็บไปทำอะไร?" *(ติดต่อกลับ / ส่งโปร / วิเคราะห์ / ยิงแอด)*
3. "ส่งข้อมูลให้ใครอีกไหม?" *(Google Analytics / Meta Pixel / อีเมล/CRM / **AI เช่น chatbot ChatGPT** / payment)*
4. "มีปุ่มติดตาม/คุกกี้วิเคราะห์-โฆษณาไหม?" *(GA/Pixel/TikTok = ต้อง consent)*
5. "มี chatbot / AI ตอบลูกค้าไหม? เก็บบทสนทนาไหม?"
6. "ใครดูแลข้อมูล + ช่องทางติดต่อ (อีเมล/เบอร์)?" *(ผู้ควบคุมข้อมูล / DPO ถ้ามี)*
7. "ธุรกิจเกี่ยวข้อมูลอ่อนไหวไหม (สุขภาพ/ศาสนา/ชีวมิติ/เด็ก<10)?" *(ถ้าใช่ → เตือนต้องเข้มพิเศษ+ทนาย)*

ขาด → ถาม/จด. สรุปยืนยัน → Phase 1.

## Phase 1 — Data Mapping (ทำ RoPA ย่อ)

ทำตารางเบื้องหลัง: **ข้อมูลอะไร → เก็บทำไม (วัตถุประสงค์) → ฐานอะไร → เก็บนานแค่ไหน → ส่งใคร (ผู้ประมวลผล/ต่างประเทศ)**.

ฐานที่ใช้บ่อยบนเว็บ:
- **ความยินยอม (consent)** — คุกกี้การตลาด/วิเคราะห์, สมัครรับข่าว → ต้องกดยินยอมก่อน
- **สัญญา** — กรอกฟอร์มเพื่อรับบริการ/ซื้อของ
- **ประโยชน์โดยชอบด้วยกฎหมาย** — คุกกี้จำเป็น, ความปลอดภัย (ต้องชั่งน้ำหนัก)

ธงแดง: ส่งข้อมูลออกนอกประเทศ (AI/cloud ต่างชาติ), profiling/automated decision, ข้อมูลอ่อนไหว → mark ไว้จัดการ Phase 6.

---

## Phase 2 — เอกสาร (ภาษาไทย)

สร้าง 2 ไฟล์ ภาษาเข้าใจง่าย ตามที่ map มา:
- **นโยบายความเป็นส่วนตัว (Privacy Policy)** — เก็บอะไร, ทำไม, ฐานอะไร, ส่งใคร (list ผู้ประมวลผลรวม AI/analytics), เก็บนานเท่าไหร่, สิทธิเจ้าของข้อมูล, ช่องทางติดต่อ, **การส่งข้อมูลออกต่างประเทศ**
- **นโยบายคุกกี้ (Cookie Policy)** — แบ่งหมวด: จำเป็น / วิเคราะห์ / การตลาด + รายการคุกกี้ + วิธีปฏิเสธ

หน้า policy วางที่ footer ทุกหน้า.

---

## Phase 3 — Cookie Consent Banner

โค้ด banner ติดเว็บ:
- เด้งก่อนโหลดคุกกี้ **non-essential** (วิเคราะห์/การตลาด)
- แยกหมวดให้ **เลือกเปิด-ปิดได้** (ไม่ใช่ปุ่ม "ยอมรับ" อย่างเดียว) + "ปฏิเสธทั้งหมด" เท่าที่ทำได้
- **ไม่ยิง GA4/Pixel/TikTok จนกว่าจะกดยินยอม** (consent mode) — จุดพลาดบ่อย
- **บันทึกหลักฐาน consent** (เวลา+ตัวเลือก) · เปลี่ยนใจภายหลังได้
- คุกกี้จำเป็น (session/ความปลอดภัย) ไม่ต้องขอ แต่ต้องแจ้ง

⚙️ แนะนำ: เขียนเอง (เบา) หรือใช้ตัวช่วย (Cookiebot/CookieYes) ตามขนาดงาน.

---

## Phase 4 — Form Consent

ทุกฟอร์มเก็บข้อมูล (ติดต่อ/สมัคร/ดาวน์โหลด):
- **checkbox ยินยอม** (ไม่ติ๊กมาให้ล่วงหน้า) + ระบุวัตถุประสงค์สั้นๆ + ลิงก์ policy
- ขอเท่าที่จำเป็น (ข้อมูลน้อยสุด = ทั้ง PDPA + convert ดี)
- แยกความยินยอม **การตลาด** ออกจากการรับบริการ (ห้ามบังคับพ่วง)

---

## Phase 5 — สิทธิเจ้าของข้อมูล (DSR)

ช่องทางให้ลูกค้าใช้สิทธิ: **ขอเข้าถึง / แก้ไข / ลบ / ถอนความยินยอม / คัดค้าน / ขอโอน**.
- อย่างน้อย: อีเมล/ฟอร์มติดต่อ DPO + สัญญาว่าจะตอบในกรอบเวลา
- ระบุในนโยบาย + จุดที่หาเจอง่าย

---

## Phase 6 — AI-specific (จุดยุคนี้) ⭐

ถ้าธุรกิจใช้ AI กับข้อมูลส่วนบุคคล ต้องเพิ่ม:
1. **เปิดเผยการใช้ AI** — ถ้ามี chatbot/AI ประมวลผลข้อมูลลูกค้า → แจ้งในนโยบาย
2. **ผู้ประมวลผลภายนอก + ข้ามพรมแดน** — ส่งข้อมูลเข้า OpenAI/Anthropic/Google ฯลฯ = (ก) list เป็นผู้ประมวลผล (ข) มีข้อตกลงประมวลผลข้อมูล/DPA (ค) แจ้งว่าส่งออกต่างประเทศ + ฐานรองรับ
3. **ห้ามป้อน personal data เข้า AI สาธารณะโดยไม่มีฐาน/ไม่แจ้ง** — โดยเฉพาะข้อมูลอ่อนไหว. ปิด training ฝั่ง vendor ถ้าทำได้ (business/API tier)
4. **profiling / automated decision** — ถ้า AI ตัดสิน/จัดกลุ่มลูกค้าอัตโนมัติที่กระทบเขา → แจ้ง + ให้สิทธิคัดค้าน/ขอคนตรวจ
5. **data minimization กับ AI** — ส่งเข้า AI เท่าที่จำเป็น, mask ข้อมูลระบุตัวตนเมื่อได้
6. **เก็บบทสนทนา chatbot** = personal data → มีวัตถุประสงค์+ระยะเก็บ+ความปลอดภัย

---

## Phase 7 — Checklist + Apply

```
□ Privacy Policy + Cookie Policy ไทย ครบ, ลิงก์ footer ทุกหน้า
□ Cookie banner: แยกหมวด, ปฏิเสธได้, ไม่ยิง tracker ก่อน consent, บันทึก consent
□ ทุกฟอร์ม: consent checkbox (ไม่ติ๊กล่วงหน้า) + วัตถุประสงค์ + ลิงก์ policy
□ ช่องทางใช้สิทธิ DSR + ผู้ติดต่อ/DPO
□ AI: เปิดเผย, list ผู้ประมวลผล (OpenAI/Claude/GA/Pixel), ข้ามพรมแดนแจ้ง, ปิด training ถ้าได้
□ ข้อมูลอ่อนไหว/เด็ก: จัดการเข้ม + เตือนให้ทนายตรวจ
□ ความปลอดภัย: https, จำกัดสิทธิเข้าถึง
```

**Apply:** ต่อกับเว็บ web-builder → ติดตั้ง policy page + banner + form consent ลงจริง. **จบที่ preview → เจ้าของ/ผู้ดูแลอนุมัติ → ขึ้น prod** (รันในเครื่อง Mark = ยึด deploy policy ของ Mark).
